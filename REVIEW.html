1. What this project is

This is a computational-neuroscience software build centered on Geometric-Informed Basis Functions (GBFs). It will expose the method's data path, assumptions, nominal source-pair scores, and failure conditions so another researcher can inspect what the selected forward model supports.

The project asks how much two spatially separated source hypotheses resemble each other at the scalp under one verified head model, declared montage, reference, and noise covariance. Similar predicted patterns indicate model-based ambiguity, not proof that either source generated the recording.

What Track A already provides

A pinned upstream GBFs path, independent numerical parity, a nominal source-signature library, distant ambiguity pairs, and an MNE resolution comparison. These are sealed development artifacts, not population validation.

2. Research question and claim boundary

Primary question: Under one declared head model, montage/reference, source family, and noise covariance, which spatially separated source hypotheses predict distinguishable scalp patterns, and which remain nominally confusable?

ui = C−1/2gi / ‖C−1/2gi‖   ;   ρij = |uiTuj|

The current score compares whitened leadfield signatures while ignoring source amplitude and polarity. A high score means the fixed model predicts similar scalp patterns for the pair. This is a nominal model comparison, not a calibrated probability that a real brain source can be recovered. Pairwise ambiguity is not automatically transitive, so the tool must not turn it into clusters without a separately justified rule.

Localize-MI stimulation contacts provide a reference for the electrical pulse-artifact task only. They do not provide ground truth for the distributed physiological response or all endogenous brain activity.

3. Existing method, reverse engineering, and possible contribution

GBFs reproduction scope

Track A pins the upstream GBFs checkout and traces the recorded-data path. On the same real Localize-MI inputs, the independent parity result has relative Frobenius difference 2.23e-13. This establishes numerical agreement for that path and those inputs; it is not reproduction of every GBFs paper benchmark or validation of source localization.

Nominal distinguishability tool

Track B exposes the nominal score through a tested API and CLI. B4 pivoted because the available Localize-MI endpoint is a stimulation pulse artifact, not a test of endogenous neural-source recovery. B7 found that the diagnostic gives a related but distinct view from MNE point-spread summaries on the same model, but no researcher decision benefit has been demonstrated. The bounded tool is retained without utility or novelty claims; package review and release checks remain open.

Closest prior art

Source-resolution matrices, point-spread/cross-talk functions, pairwise source separability, leadfield similarity, and forward-model uncertainty have substantial prior art. The current collision audit rejects a broad claim that identifying indistinguishable source patterns is new. Any extension must be specified exactly, compared with matched established methods, and shown to change a researcher decision.

4. Real data and forward-model limits

The intended case is Localize-MI sub-01 with its participant-specific forward solution, recorded scalp EEG, stimulation-event metadata, and contact coordinates. Track A records dataset snapshot d7a123d3067213281f106b343c71f28c30e4dd60, 236 usable scalp channels, 8,196 fixed-orientation cortical vertices, and six primary 1 mA stimulation sites. All sub-01 results are development data.

The head model, reference projection, covariance estimate, source orientation, and distance threshold affect the nominal score. Results are limited to this participant and these declared assumptions. The stimulation contacts are a reference for the pulse artifact, not ground truth for the distributed physiological response.

Active scientific analyses use real recordings only. The Track A release and outputs remain sealed; new work gets new run IDs. Use CPU float64 as the correctness reference and GPU only for an eligible real computation after CPU checks pass.

7. Validation rules

  • Use only real recordings for active experiments and comparisons. Historical synthetic artifacts are excluded from current evidence and must not be extended into active synthetic tests.
  • Use real recordings only and keep the sealed Track A release unchanged.
  • Report nominal source-pattern distinguishability separately from measured pulse-artifact localization.
  • Match forward model, montage, reference, covariance, source family, and reporting scale across comparisons.
  • Keep pairwise ambiguity distinct from clusters, calibrated uncertainty, and true anatomical recovery.
  • Report uncertainty, failed fits, exclusions, negative controls, and deviations. Do not select analysis choices because they improve confirmatory results.
  • Any change informed by reserved participant outcomes retires that participant from independent confirmation.

B5/B6 are not active under the current route because B4 found no supported endogenous-source endpoint in the available Localize-MI data. Do not open held-out outcomes or report population performance. Reopening confirmatory analysis requires a distinct real-data endpoint, prior-art screen, and locked protocol.

8. What counts as a complete build

The project is complete only when the gate register reaches a justified terminal state and an independent person can reproduce the eligible real-data analysis from the documented software.

  • A validated, pinned real-data workflow with explicit licensing, provenance, participant split, preprocessing, and synchronization limits.
  • A verified GBFs implementation and documented reverse-engineering path.
  • A source-distinguishability tool compared fairly with standard resolution and separability diagnostics on permitted real data.
  • A mathematical addition only if its distinction survives prior-art review and changes a prespecified decision; otherwise, make no novelty claim.
  • Installable software, command-line instructions, configuration examples, tests for mathematical and software invariants, reproducible run manifests, and an inspectable report.
  • An independent technical check of the clean-room method implementation and the scientific claim boundaries.
Success is evidence-led: a negative or mixed result can still produce a strong research software build if it clearly identifies when the method succeeds, when it fails, and what the dataset cannot establish.
