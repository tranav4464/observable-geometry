# NeuroFlowNet paper-to-source fidelity matrix

> **Historical route audit, superseded 23 October 2026.** NeuroFlowNet is not the active build baseline. Retain this matrix as prior-route research only; current GBFs specifications and gate state are in `B2_GBF_SPEC.md` and `GATE_REGISTER.json`.

**Purpose:** define what can be implemented from the published method, what the pinned public source clarifies, and what must remain an explicit adaptation. The author repository has no declared license in the inspected snapshot. It is used only as read-only evidence; no source code is copied, executed, or incorporated.

## Component-by-component findings

| Component | Paper specifies | Pinned source clarifies | B3 implementation boundary |
|---|---|---|---|
| Conditional task | `p(X_t | X_c)`; target iEEG and context scalp EEG have shape `[channels, time]`; maximum-likelihood training. | Uses a channel-first PyTorch sequence representation and conditions the flow on scalp channels. | Implement the conditional density and prediction API with scalp input only at inference. This is the stated task, not a claim to recover latent sources. |
| Affine coupling forward map | Eq. 1: `z_b = (x_b + τ) ⊙ exp(σ)`. The Jacobian log absolute determinant is `sum(σ)`. | Uses this same forward map. Its training entry point uses `τ = 10 tanh(raw_τ)` and clips `σ` to `[-5,5]`. | Use the forward map as printed. Treat the factor 10 as a method-detail resolution from Algorithm 1 and the source; paper prose elsewhere describes only `tanh` bounded to `[-1,1]`, so record that discrepancy. |
| Affine coupling inverse | Eq. 4 and Algorithm 2 print `x_b = exp(-σ) ⊙ (z_b − τ)`. | The source computes `x_b = z_b ⊙ exp(-σ) − τ`. | The printed Eq. 4/Algorithm 2 do **not** invert Eq. 1. Derive and use `x_b = z_b ⊙ exp(-σ) − τ`, which is the exact inverse of the stated forward map and matches the inspected source. Label this an algebraic correction to the paper text. Add direct forward/inverse and Jacobian checks before any fit. |
| Conditional network | Describes Conv1d kernels 3 then 1 with ReLU, multi-head self-attention, then a kernel-3 output convolution. | Concatenates the unchanged target half with scalp context before the first convolution; applies attention over time with PyTorch multi-head self-attention; outputs shift and log-scale. The training config uses 8 attention heads. | These tensor wiring and attention details are clarified by source, not fully specified in paper. Implement independently and label as source-informed reconstruction. Residual connections, normalization, attention masks, positional encodings, and exact initialization are not established by the paper; do not silently invent paper fidelity for them. |
| Invertible channel mixing | A learned `1×1` matrix `W`; log determinant is `L log|det(W)|`; paper states QR-based orthogonal initialization. | Applies one channel-mixing operation per flow step and initializes `W` using QR. | Specified well enough to implement; verify `slogdet`, inverse, and Jacobian against float64 calculations. |
| Multi-scale factorization | Repeats `N_steps` per scale, extracts half the channels as latent at each scale, propagates the remaining half, and concatenates latent parts. | Uses sequential channel halving and reverses scales for sampling. | Project rule: split `left=floor(C/2)`, `right=C-left`, preserving channel order; stop if a scale has fewer than two channels for a coupling step. This is an explicit adaptation because the paper does not define odd-channel behavior. Metadata-only channel counts support the selected two-scale structure for all audited participants. |
| Base distribution and sampling | Standard multivariate normal latent and inverse-flow conditional sampling. | Samples standard-normal latent values and applies inverse scales/steps; no temperature parameter is used in the inspected sampling path. | Use `N(0,I)` as the canonical sampler. Any temperature or calibrated sampling adjustment would be a new adaptation and must be separately evaluated. |
| Likelihood reduction | Change-of-variables sum of base log density and all step log determinants. Algorithm 1 sums over channel/time coordinates and averages over the batch. | Computes the same summed-coordinate likelihood in its training path. | Implement per-example log likelihood with explicit coordinate sum, then batch mean for optimization; add a small independently calculated likelihood check. |
| Published training values | AdamW `lr=1e-3`, `weight_decay=1e-2`, batch 128, maximum 100 epochs, early-stopping patience 10; selected `N_S=2`, `N_steps=6`, `C_h=128`. | Main entry point uses batch 64, maximum 500 epochs, patience 10, and `ReduceLROnPlateau(mode='max', patience=5)` while passing validation loss to the scheduler. It sets 8 attention heads. | Paper values are the starting target for clean-room reproduction. The source training schedule is not interchangeable with the paper description; in particular, a max-mode scheduler receiving a loss is inconsistent with minimizing loss. Any adapted schedule must be explicit and use development-only decisions. |
| Preprocessing / segmentation | Sym4 3-level DWT with segment MAD threshold; downsample iEEG to 200 Hz after anti-alias filtering; 200-sample one-second windows, 90% overlap for training and no overlap for evaluation; per-segment z-scoring. Numeric filter and some ordering details are absent. | Repository preprocessing is trial-based and the previously audited snapshot does not implement the paper's reported whole-session holdout. It stores target segment scale for validation inverse-scaling. | Use the active B2 adaptation, not a false claim of exact preprocessing reproduction. Do not use held-load target statistics for inference or physical-unit restoration. |

## Decision

The model family is mathematically implementable, but an **exact paper reproduction cannot be claimed from the available specification**. The inverse equation is inconsistent with the printed forward map, and the public source resolves the intended inverse while differing from some paper-reported training settings. The conditional network also has implementation details the paper does not pin down. B3 may proceed only after B2 passes, as a clean-room, source-informed implementation with the inverse correction and all remaining adaptations visible in the config and report. No novelty or invalidity claim follows from this audit.
